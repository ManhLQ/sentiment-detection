# App Idea Generator - Usage Guide

## Overview

The App Idea Generator is a DSPy-powered module that creates comprehensive, validated app ideas based on your requirements. It takes into account domain, complexity level, and additional constraints to generate practical, buildable app concepts.

### How It Works

The generator uses **few-shot learning** with DSPy:
- **Not template-based**: Ideas are generated by the LLM, not copied from templates
- **Example-guided**: The LLM learns from 4 high-quality training examples covering different complexity levels
- **Pattern recognition**: The LLM understands the structure, style, and quality expectations from examples
- **Novel generation**: Each idea is unique and tailored to your specific requirements
- **Use-case focused**: Concentrates on WHAT to build (features, users, value) not HOW (tech stack)

This approach ensures consistent quality while maintaining creativity and avoiding repetitive outputs.


## Quick Start

### Basic Usage

```bash
# Generate a simple productivity app
python src/cli.py ideas -d "productivity" -c low

# Generate a medium complexity project management app
python src/cli.py ideas -d "project management" -c medium

# Generate a complex education platform
python src/cli.py ideas -d "education" -c high
```

### With Additional Requirements

```bash
# Add specific constraints
python src/cli.py ideas \
  -d "fitness tracking" \
  -c medium \
  -r "must support offline mode and data sync"
```

## Command-Line Options

### Required Arguments

- `--domain`, `-d`: Domain or seed idea (e.g., 'project management', 'fitness tracking')

### Optional Arguments

- `--complexity`, `-c`: Complexity level - `low`, `medium`, or `high` (default: medium)
- `--requirements`, `-r`: Additional requirements or constraints
- `--format`, `-f`: Output format - `json`, `markdown`, or `terminal` (default: terminal)
- `--output`, `-o`: Output file path (saves to file instead of stdout)
- `--verbose`, `-v`: Show generation progress and validation details
- `--debug`: Show DSPy prompt history for debugging

## Complexity Levels

### Low Complexity
- **Build Time**: 1-2 weeks
- **Features**: 2-4 core features
- **Data Models**: 2-4 simple entities
- **Integrations**: None or minimal
- **Example**: Pomodoro timer, simple note-taking app

### Medium Complexity
- **Build Time**: 3-6 weeks
- **Features**: 4-8 features with some complexity
- **Data Models**: 5-10 entities with relationships
- **Integrations**: 1-2 external services
- **Example**: Project management tool, API caching service

### High Complexity
- **Build Time**: 2-3 months
- **Features**: 8+ features with advanced functionality
- **Data Models**: 10+ entities with complex relationships
- **Integrations**: Multiple external services
- **Example**: Learning platform, social network

## Output Formats

### JSON
```bash

```

Structured JSON output suitable for programmatic use.

### Markdown
```bash
python src/cli.py ideas -d "fitness" -c low -f markdown -o idea.md
```

Well-formatted markdown suitable for documentation.

## Output Structure

Every generated idea includes:

- **Name**: Catchy, memorable app name
- **Tagline**: One-sentence description
- **Description**: Detailed explanation of what the app does
- **Target Users**: Who would use this app
- **Core Features**: Organized by priority (Core, Important, Nice-to-Have)
- **Complexity Justification**: Why this matches the requested complexity
- **Estimated Build Time**: Rough time estimate
- **Unique Selling Point**: What makes this idea special

**Note**: All ideas are automatically saved to the `output/` folder in markdown format using the app name as the filename.

## Programmatic Usage

```python
from ideas import AppIdeaGenerator, IdeaRequest, ComplexityLevel

# Create generator
generator = AppIdeaGenerator()

# Create request
request = IdeaRequest(
    domain="fitness tracking",
    complexity=ComplexityLevel.MEDIUM,
    additional_requirements="offline support and data sync"
)

# Generate idea with validation
idea, metadata = generator.generate_with_validation(
    request=request,
    verbose=True
)

# Access idea properties
print(f"App Name: {idea.name}")
print(f"Features: {len(idea.core_features)}")
print(f"Build Time: {idea.estimated_build_time}")

# Save to file
from ideas import format_as_markdown, save_to_file
markdown = format_as_markdown(idea)
save_to_file(markdown, "my_idea.md")
```

## Tips for Best Results

1. **Be Specific with Domain**: Instead of "app", use "fitness tracking for runners" or "project management for small teams"

2. **Use Requirements Wisely**: Add constraints that affect features, not implementation:
   - ✅ Good: "must work offline", "real-time collaboration", "mobile-first"
   - ❌ Avoid: "use FastAPI", "PostgreSQL database" (these are implementation details)

3. **Match Complexity to Goals**: 
   - Learning project? → Low complexity
   - Portfolio piece? → Medium complexity
   - Startup MVP? → Medium to High complexity

4. **Iterate**: Use `--verbose` to see validation feedback and regenerate if needed

## Troubleshooting

### Long Field Values

The generator automatically truncates fields that exceed maximum lengths:
- App name: 50 characters
- Tagline: 150 characters
- Description: 500 characters
- Target users: 200 characters
- Feature name: 100 characters
- Feature description: 300 characters
- Unique selling point: 300 characters
- Complexity reasoning: 500 characters

If you see "..." at the end of a field, it was truncated. This is normal and prevents validation errors.

### Validation Failures

If an idea fails validation:
1. The generator will automatically retry (up to 2 times)
2. Use `--verbose` to see validation issues
3. Use `--debug` to inspect LLM prompts and responses
4. Adjust your requirements to be clearer

### LLM Configuration

The generator uses the LLM configured in your `.env` file:
- OpenAI: Set `LLM_BACKEND=openai` and `OPENAI_API_KEY`
- Ollama: Set `LLM_BACKEND=ollama` and `OLLAMA_BASE_URL`

## Advanced Features

### Debug Mode

```bash
python src/cli.py ideas -d "fitness" -c low --debug
```

Shows the exact prompts sent to the LLM and raw responses, useful for:
- Understanding how DSPy constructs prompts
- Debugging unexpected outputs
- Improving prompt engineering

### Automatic Saving

All generated ideas are automatically saved to `output/<app_name>.md` regardless of the `--output` flag. This provides a convenient archive of all your generated ideas.

## What Makes a Good Idea?

The generator aims to create ideas that are:

1. **Practical**: Can actually be built within the specified complexity
2. **Valuable**: Solves a real problem for real users
3. **Scoped**: Clear boundaries and well-defined features
4. **Interesting**: Unique angle or approach that makes it engaging to build
5. **Focused**: Concentrated on core value proposition, not feature bloat

## Next Steps

After generating an idea:

2. **Choose Your Stack**: Select technologies based on your preferences and expertise
3. **Plan Implementation**: Break down features into tasks
4. **Start Building**: Use the idea as a blueprint for your project

The generator provides the **what** - you decide the **how**!
